# Adopt Flutter after native integration spikes

Cirrava provisionally selects Flutter for its shared Android-phone and iPhone interface because it offers solo-development velocity, precise custom rendering, and one primary UI implementation. The decision becomes accepted only after physical-device spikes demonstrate a polished flight-detail screen on both phone platforms, a Swift bridge that starts, updates, and ends an iOS Live Activity, and a Kotlin bridge that starts, updates, and ends an Android Live Update. Native integrations remain behind narrow interfaces. A concrete framework blocker in any spike reopens the comparison with Kotlin Multiplatform, React Native, and separate native applications before production features accumulate.

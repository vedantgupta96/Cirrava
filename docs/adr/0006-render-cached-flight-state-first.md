# Render cached flight state first

Cirrava immediately renders the last accepted Cached Flight State for a followed flight and refreshes it in the background. The local database is the mobile interface's sole data source: network responses are written transactionally before observers update and never bypass persistence. The interface always communicates Data Freshness; a failed refresh leaves cached information visible with an offline or stale indicator instead of replacing it with an error screen. Only a Flight Instance that has never loaded successfully has no cached state. V1 offline behavior is otherwise read-only: searching for or starting a new Flight Follow requires connectivity. Stopping a follow takes effect locally immediately and queues the server removal, but v1 does not include a general offline mutation-sync engine. This requires deliberate local persistence and stale-data presentation but makes the agreed v1 follow experience reliable in airports, airplanes, and poor connectivity.

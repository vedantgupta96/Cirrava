# Canonicalize Flight Instances by operating service

Cirrava represents one operating service segment as one Flight Instance, even when it is sold under multiple marketing flight numbers. Each Flight Instance has an immutable internal identity; the operating carrier, operating flight number, scheduled origin and destination, and scheduled local departure date are matching attributes rather than the database identity. Marketing flight numbers are Codeshare Aliases and provider identifiers are external references. When a schedule change moves departure across local midnight, the existing Flight Instance survives if provider continuity indicates the same operation. A different operation created after cancellation is a linked Replacement Flight rather than a rewrite of the cancelled Flight Instance. An existing Flight Follow does not transfer automatically: Cirrava preserves the cancelled follow and offers an explicit action to follow the replacement. This preserves identity, intent, events, and notifications, at the cost of requiring explicit reconciliation when schedules or provider records change.

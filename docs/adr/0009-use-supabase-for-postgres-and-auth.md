# Use Supabase for PostgreSQL and authentication

Cirrava uses Supabase for managed PostgreSQL and authentication while the NestJS API and worker own flight-domain behavior. The mobile app uses Supabase directly only for authentication and session management; all application data flows through the NestJS API so authorization, follow limits, canonical identity, and domain invariants have one enforcement path. PostgreSQL Row Level Security remains defense in depth rather than a second client data path. Provider access, polling, webhook ingestion, normalization, identity reconciliation, event generation, notification planning, and long-running jobs remain in dedicated backend processes rather than Supabase Edge Functions. This reduces database and identity operations for a solo-developed product while preserving a portable relational model and explicit application boundaries.

# Separate Flight Events from notification decisions

A Flight Event records meaningful history but does not automatically produce a user notification. Cirrava makes a separate server-side Notification Decision using event severity, change thresholds, follower preferences, quiet hours, and delivery eligibility, then records and retries delivery independently. An Anonymous User receives a fixed, non-customizable set for the one Active Flight Follow: terminal or gate assignment and change; a Material Delay, followed by another notification only when the estimate moves by at least 15 minutes from the last notified value or crosses back below the threshold; boarding or gate closure; cancellation, diversion, return to gate, or Replacement Flight availability; and departure, landing, or arrival at gate. OS-level notification controls still apply. This separation adds an explicit planning stage but prevents push infrastructure from becoming a source of truth and allows notification policy to evolve without rewriting flight history.
